# 跑团桌 · TRPG Table

## 它是什么

跑团桌是 DeepSeek Harness 的多人跑团插件：房主在自己电脑上开一间房，朋友用各自的 DSH 客户端加入；AI 担任 KP/GM，负责场景叙事、NPC 扮演、掷骰与全部数值结算；玩家只提交「我的角色要做什么」并 RP。

目标是把「C 位永远是玩家」还给跑团：AI 不当裁判、不抢戏、不替玩家做决定，只把规则与世界的反应呈现出来。

## 核心设计

- **确定性引擎**：掷骰、检定、伤害、先攻、状态由插件内的纯函数引擎结算；AI 通过工具拿结论写叙事，自己写出的数字不进入状态。
- **身份绑定**：玩家行动由服务端绑定到该玩家角色，AI 不推断「谁在行动」。
- **状态唯一写者**：角色状态只有引擎能改，事件日志可回放。
- **行动许可**：探索自由行动；战斗由服务器维护先攻轮（已接入，AI 走 `trpg_*` 战斗工具）。
- **按人投影**：每个玩家只收到自己可见的公共叙事 + 私密层，私密信息在网络层就不会发给别人。
- **双 GM 模式**：AI GM（默认）与真人 GM（AI 当助手）共用同一套引擎与右侧栏常驻卡片。

## 当前版本：M6（对话原生牌桌，本机实机验收通过 2026-11-16）

> 本机单机链路已验收（主区域=DSH 原生对话、头部入口打开右侧栏「跑团桌」页签、320/360px 栏宽布局正常、建房自动绑定会话、结束房间=关房解绑）；**局域网双机（host + 另 1–3 台真机）验收待执行**。M7 玩家侧对话镜像未实现。

- 房主端房间服务（`0.0.0.0:45871`）：`/trpg/rpc`、`/trpg/events`（SSE）、`/trpg/health`、`/trpg/rooms`。
- AI GM：房间绑定房主当前打开的会话（建房带 `sessionId` 或 `room.bind`），插件在该会话 Agent 上注册 GM 提示段与 `trpg_*` 工具；玩家行动以 `user/message` 注入会话，GM 的 assistant 文本回写房间事件（玩家端/战报用）。
- GM 工具（均带 `trpg_` 前缀）：`trpg_roll_check`（引擎检定）、`trpg_roll_dice`、`trpg_secret_note`（私密）、`trpg_reveal_lore`、`trpg_check_lore`、`trpg_list_party`、战斗工具等；只注册在牌桌会话 Agent 作用域。
- 客户端：「🎲 跑团桌」入口（正常对话页在对话头部；DSH「新会话」空态页在左上角，点它会先准备一个会话再打开右侧栏）+ 右侧栏「跑团桌」tab 常驻卡片（建房/加入/落座/玩家席/掷骰/GM 控制台/成长战报）；不自绘聊天页、无插件输入框（v2 的主区域整页面板已废弃）。
- 断线重连：SSE 带 `lastSeq` 补发错过的事件，私密事件在补发时同样过滤。
- 规则引擎：D&D 5e-lite（检定/战斗/先攻/法术位），内容含 4 角色卡、世界书与模组「鬼木崖·异光」。

后续里程碑（M7 玩家侧对话镜像、局域网实机验收）见仓库根目录 `docs/ROADMAP.md`。

## 限制

- 房间存档在 DSH profile-data 目录，重启后自动恢复；牌桌会话需重新打开（只有 live 会话能发模型请求）。
- 重载后 localStorage 残留旧房 token 会红字提示「无法恢复房间：令牌无效或已失效」，应改为静默清理（尚未做）。
- 页签已打开时再点头部「🎲 跑团桌」会重开页签（短暂空白 + 右栏宽度回默认），不产生重复页签。
- 玩家「退出房间」只离席、不关房（设计如此）；房主「结束房间」才关房并解绑牌桌会话（GM 提示与 `trpg_*` 工具随之撤销）。
- 玩家侧原生会话镜像（M7）尚未实现。
- 局域网明文 HTTP，仅限内网；公网/QQ 接入是 v2。
- Windows 首次监听端口时防火墙可能弹窗，需要允许专用网络访问。
