# 跑团桌 · TRPG Table

## 它是什么

跑团桌是 DeepSeek Harness 的多人跑团插件：房主在自己电脑上开一间房，朋友用各自的 DSH 客户端加入；AI 担任 KP/GM，负责场景叙事、NPC 扮演、掷骰与全部数值结算；玩家只提交「我的角色要做什么」并 RP。

目标是把「C 位永远是玩家」还给跑团：AI 不当裁判、不抢戏、不替玩家做决定，只把规则与世界的反应呈现出来。

## 核心设计

- **规则即数据**：规则包由 JSON 数据 + 受限公式 + 固定 JS 钩子组成，在 `node:vm` 沙箱中执行；引擎不认识具体规则。
- **确定性结算**：掷骰、检定、伤害、先攻、移动、行动经济由主机规则运行时结算；AI 通过工具拿结论写叙事，自己写出的数字不进入状态。
- **身份绑定**：玩家行动由服务端绑定到该玩家角色，AI 不推断「谁在行动」。
- **状态唯一写者**：角色状态只有规则运行时可改，事件日志可回放。
- **按人投影**：每个玩家只收到自己可见的公共叙事 + 私密层；玩家侧还能在**本机原生会话**里看整局镜像。
- **双 GM 模式**：AI GM（默认，绑定房主当前会话）与真人 GM 控制台共用同一套运行时与右侧栏卡片。
- **内容包**：模组/世界书/角色卡统一 `.trpgpack`，可导入导出、编辑、分享。

## 限制

- 玩家镜像只读：行动仍由房主在牌桌会话代录；镜像会话里直接发言不会进房间，玩家端无 key 时原生 prompt 会报错。
- AI GM 只能绑定当前在 DSH 里打开的会话（live）；插件新建/恢复的会话发模型请求会 transport 失败。
- 重载后 localStorage 残留旧房 token 会红字提示「无法恢复房间：令牌无效或已失效」（未静默清理）。
- 页签已打开时再点头部入口会重开页签（短暂空白，不产生重复页签）；≈300px 极窄 + 多页签时页签标题截断。
- 玩家「退出房间」只离席、不关房（设计如此）；房主「结束房间」才关房并解绑牌桌会话。
- 局域网明文 HTTP，仅限内网；公网/QQ 接入是 v2；Windows 首次监听端口需允许防火墙（TCP 45871）。
- 工坊写操作与生图仅 loopback + host token；内置包只读；zip 不支持 zip64/加密/分卷；资产只收 PNG/SVG（拒 JPEG/WebP）。
- 完整已知限制与验收口径见仓库 `docs/ACCEPTANCE.md` §3。
