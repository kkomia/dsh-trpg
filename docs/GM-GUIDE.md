# GM / 房主手册（跑团桌 · TRPG Table）

> 你是房主：房间、存档、AI GM 都跑在你这台电脑上。玩家只需要安装插件并连到你的局域网地址。

> **UI v3（2026-11-16）**：跑团桌不自绘聊天页——房主当前打开的 DSH 会话就是牌桌，入口在对话头部「🎲 跑团桌」按钮 / 右侧栏「跑团桌」tab（常驻卡片）。**本机单机链路已实机验收通过（2026-11-16）**；局域网双机验收待做。本手册已按 v3 更新。

## 1. 建房

1. 先在 DSH 里打开一个会话（它将成为牌桌会话）。**只有正在 DSH 里打开、被页面驱动的会话才能让 AI 回话**；插件新建/恢复的会话会 transport 失败；
2. 点对话头部「🎲 跑团桌」→ 右侧栏出现「跑团桌」tab；
3. 「开团 · 我是房主」：填团名、选 **AI 当 GM** 或 **真人 GM** → **创建房间**（会把当前会话绑定为牌桌）；之后也可在房间卡片点「绑定当前会话 / 改绑到本会话」；
4. 记下 **6 位邀请码**（只有房主能看到），把「你的局域网地址 + 邀请码」发给朋友；
5. 确认你的局域网 IP：`ipconfig` 里 IPv4 地址，房间服务默认监听 `0.0.0.0:45871`。

> 朋友连不上：Windows 防火墙首次会弹窗，选「允许专用网络」；或手动放行 TCP 45871。

## 2. 两种模式

| | AI 当 GM | 真人 GM |
|---|---|---|
| 谁叙事 | AI（牌桌会话的 Agent，用宿主配置的模型） | 你（GM 控制台写旁白，或在会话里直接说） |
| 数值/掷骰 | 引擎结算，AI 调用 `trpg_*` 工具请求 | 引擎结算，你用掷骰/工具 |
| 开局 | 绑定会话后 AI GM 就在这个会话里；在会话里说一句开场（如「开始」）即可 | 你手动发第一段旁白 |
| 干预 | 你随时可用 GM 控制台接管 | — |

**建议**：第一次带团用 AI 模式，你同时当玩家也能玩；熟悉后再试真人 GM。

## 3. GM 控制台（房主专属）

右侧栏「跑团桌」tab 的房间卡片里点「GM 控制台」（仅房主可见，可折叠）：

- **发送旁白**：以 GM 身份向全桌描述（走与 AI 相同的叙事通道）；
- **私发**：选玩家 → 填内容 → 只有该玩家（和你）能看到；
- **推进场景**：从模组三幕里选一幕 → 全桌收到「📍场景推进」并更新房间场景标记；
- **发奖励**：选玩家 + XP + 物品（逗号分隔）→ 只有该玩家收到奖励卡（GM 可见）。

其他管理：玩家席每行「移除」（踢人）；房间卡片「锁房/解锁」；房间卡片「结束房间」（房主）= 真正关房并解绑牌桌会话（GM 提示与 `trpg_*` 工具不再注入）；玩家点「退出房间」只离席，不关房。

## 4. AI GM 的工作方式（为什么它不会串角）

- AI GM 就是**牌桌会话的 Agent**：插件在会话上注册 GM 系统提示段（人格/模组/硬规则）与 `trpg_*` 工具；GM 的回复是会话里的原生消息，工具卡由 DSH 原生渲染；
- 每个玩家行动由服务端绑定身份后以用户消息注入会话，prompt 里明确「本次只有这一位玩家行动」；
- AI 想掷骰/检定必须调用工具，骰面与成败由引擎算出，AI 不能自己编数字；
- AI 只能通过 `trpg_secret_note` 私发信息；世界书里的 GM 秘密不会直接说破；
- 战斗里 AI 只能让「当前行动者」攻击，抢回合会被引擎拒绝。

## 5. 存档与续团

- 房间状态自动存档到：
  `C:\Users\<你>\.dsh\profile-data\desktop\dsh-trpg-table\rooms\<roomId>.json`
  （每次事件后 800ms 内落盘，原子写）；
- **DSH 重启后自动恢复房间**：你和玩家刷新页面/重开 DSH，用原来的地址+令牌重连即可续团；
- **牌桌会话需重新打开**：房间恢复后，只有你重新在 DSH 里打开该会话（live）才能让 AI 继续回话；右栏卡片可查看/改绑牌桌会话；
- **结束房间 = 关房并解绑**：房主点「结束房间」后房间从存档移除（重启不会恢复），会话上的 GM 提示与 `trpg_*` 工具撤销；玩家「退出房间」只离席，不关房；
- 手工备份：复制上述目录即可；删除对应 json 再重启 = 丢弃该房间。

## 6. 模组与内容

- 内置模组「鬼木崖·异光」：3 幕（接悬赏 → 查古洞 → 守关战），45 分钟左右；
- 预制角色卡 4 张、世界书 10 条（含 3 条 GM 秘密）、怪物 12 种；
- 想改内容：编辑 `packages/content/modules/guimuya.json`（格式见 `docs/DESIGN.md` §6），重新 build 后重启 DSH；
- 自制模组注意：`scene.entry` 是开场旁白、`checks` 的 skill 用英文 id（如 `perception`）、`encounters.monsters.monsterId` 必须是 `MONSTERS` 里的 id。

## 7. 疑难

| 现象 | 处理 |
|---|---|
| 玩家连不上 | 防火墙；确认同一网段；确认房间服务健康：浏览器打开 `http://<你的IP>:45871/trpg/health` |
| 绑定报「这个会话当前没有活动的 AI」 | 会话没有在 DSH 里打开（不是 live）；先打开该会话再点「绑定当前会话」 |
| 「AI GM 启动失败」 | 你的 DSH 模型配置不可用；检查设置→模型；房间仍可用真人 GM 模式玩 |
| 右栏红字「无法恢复房间：令牌无效或已失效」 | 本地记着一个已结束/失效的房间；重新加入房间即可（当前版本不会静默清理旧 token，属已知限制） |
| AI 不开口 | 看右栏卡片的牌桌会话与绑定状态；确认会话已打开；在会话里再发一次行动；确认插件 Host 已加载（DSH 重启过） |
| 端口冲突 | 关掉占用 45871 的程序，或给插件改端口（plugin config `port`） |

## 8. 已知限制（M6，本机实机验收通过 2026-11-16）

- **重载后旧 token 残留**：刷新/重载 DSH 后，若 localStorage 里残留旧房 token，右栏会红字提示「无法恢复房间：令牌无效或已失效」；重进 tab 或重新加入即可。应改为静默清理（尚未做）。
- **重开 tab**：页签已打开时再点对话头部「🎲 跑团桌」会重开页签（短暂空白 + 右栏宽度回默认），不会产生重复页签。
- **玩家退出不关房**：玩家点「退出房间」只离席，房间与牌桌绑定仍由你保留；只有你点「结束房间」才关房并解绑。
- **极窄栏宽**：≈300 CSS px 且多页签时页签标题会被截断（卡片本身正常）。
- **远端玩家行动入口**：v3 删除插件输入框后，玩家行动尚无 UI 入口（随 M7 玩家镜像开放）；当前由你在牌桌会话里代录，或由回归脚本调用 `room.say`。
