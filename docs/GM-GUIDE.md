# GM / 房主手册（跑团桌 · TRPG Table）

> 你是房主：房间、存档、AI GM 都跑在你这台电脑上。玩家只需要安装插件并连到你的局域网地址。

## 1. 建房

1. 打开 DSH 任意会话 → 输入框下方「🎲 跑团桌」；
2. 「我是房主」区域：填房间标题、选 **AI 当 GM** 或 **真人 GM** → **创建房间**；
3. 记下 **6 位邀请码**（只有房主能看到），把「你的局域网地址 + 邀请码」发给朋友；
4. 确认你的局域网 IP：`ipconfig` 里 IPv4 地址，房间服务默认监听 `0.0.0.0:45871`。

> 朋友连不上：Windows 防火墙首次会弹窗，选「允许专用网络」；或手动放行 TCP 45871。

## 2. 两种模式

| | AI 当 GM | 真人 GM |
|---|---|---|
| 谁叙事 | AI（DSH Agent，用宿主配置的模型） | 你（GM 控制台写旁白） |
| 数值/掷骰 | 引擎结算，AI 调工具请求 | 引擎结算，你用掷骰/工具 |
| 开局 | 建房后 AI 自动开场 | 你手动发第一段旁白 |
| 干预 | 你随时可用 GM 控制台接管 | — |

**建议**：第一次带团用 AI 模式，你同时当玩家也能玩；熟悉后再试真人 GM。

## 3. GM 控制台（房主专属）

建房后房间视图顶部出现「GM 控制台（仅房主可见）」：

- **发送旁白**：以 GM 身份向全桌描述（走与 AI 相同的叙事通道）；
- **私发**：选玩家 → 填内容 → 只有该玩家（和你）能看到；
- **推进场景**：从模组三幕里选一幕 → 全桌收到「📍场景推进」并更新房间场景标记；
- **发奖励**：选玩家 + XP + 物品（逗号分隔）→ 只有该玩家收到奖励卡（GM 可见）。

其他管理：玩家席每行「移除」（踢人）；房间栏「锁房/解锁」。

## 4. AI GM 的工作方式（为什么它不会串角）

- 每个玩家行动由服务端绑定身份后再喂给 AI，prompt 里明确「本次只有这一位玩家行动」；
- AI 想掷骰/检定必须调用工具，骰面与成败由引擎算出，AI 不能自己编数字；
- AI 只能通过 `secret_note` 私发信息；世界书里的 GM 秘密不会直接说破；
- 战斗里 AI 只能让「当前行动者」攻击，抢回合会被引擎拒绝。

## 5. 存档与续团

- 房间状态自动存档到：
  `C:\Users\<你>\.dsh\profile-data\desktop\dsh-trpg-table\rooms\<roomId>.json`
  （每次事件后 800ms 内落盘，原子写）；
- **DSH 重启后自动恢复房间**：你和玩家刷新页面/重开 DSH，用原来的地址+令牌重连即可续团；
- 手工备份：复制上述目录即可；删除对应 json 再重启 = 丢弃该房间。

## 6. 模组与内容

- 内置模组「鬼木崖·异光」：3 幕（接悬赏 → 查古洞 → 守关战），45 分钟左右；
- 预制角色卡 4 张、世界书 10 条（含 3 条 GM 秘密）、怪物 12 种；
- 想改内容：编辑 `packages/content/modules/guimuya.json`（格式见 `docs/DESIGN.md` §6），重新 build 后重启 DSH；
- 自制模组注意：`scene.entry` 是开场旁白、`checks` 的 skill 用英文 id（如 `perception`）、`encounters.monsters.monsterId` 必须是 `MONSTERS` 里的 id。

## 7. 疑难

| 现象 | 处理 |
|---|---|
| 玩家连不上 | 防火墙；确认同一网段；确认房间服务健康：浏览器打开 `http://<你的IP>:45871/trpg/health` |
| 「AI GM 启动失败」 | 你的 DSH 模型配置不可用；检查设置→模型；房间仍可用真人 GM 模式玩 |
| AI 不开口 | 看面板状态与叙事流里的 alert；重发一次行动；确认插件 Host 已加载（DSH 重启过） |
| 端口冲突 | 关掉占用 45871 的程序，或给插件改端口（plugin config `port`） |
