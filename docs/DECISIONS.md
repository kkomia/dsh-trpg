## 第八轮：规则模型（数据 + 公式 + JS 钩子）补记（2026-11-16）

| # | 决策点 | 结论 | 备选与理由 |
|---|---|---|---|
| 26 | 规则层如何做到「任意规则可定义」，且引擎不写死 dnd5e | **规则模型已定稿（2026-11-16），M9 排期待确认**：①**脚本 API 风格 = C 混合**——JSON 数据描述「有什么」（属性/技能/装备槽与词条/动作/成长/掉落/UI），受限公式表达简单算法，JS 钩子只给 8 个固定时机（validateSheet / computeDerived / resolveCheck / resolveAttack / resolveDamage / onEvent / onLevelUp / generateLoot，外加可选 migrateSheet）用（第九轮 #27 已按「场地/时间必须进模型」扩展：新增 computeDistance / onMove / onEnterZone / onLeaveZone / computeCover / onTimeAdvance / onRoundStart / onRoundEnd，见 [`RULES-MODEL.md`](./RULES-MODEL.md) §3/§6）；②**内置示例规则包 = 把现有 dnd5e-lite 用新模型重写**（默认示例，让「鬼木崖·异光」团能继续玩，也给作者抄；dnd5e 不能写死在引擎）；③**客户端只渲染主机成果**——内容包 JS 只在 host 的 `node:vm` 沙箱跑，玩家客户端零脚本执行，只拿主机算好的投影；④**脚本存放形态 = pack zip 内独立文件**（`rules/scripts/*.js`），`pack.json` 按钩子名引用并带 sha256，可 diff/可单测/可编辑器编辑。理由：线下跑团因人工计算而简化规则与战斗，线上由电脑计算，可支撑更复杂的装备与战斗体系并做可视化（参考电子游戏装备体系与 UI）；不必完全仿照某个版本的跑团规则——装备不定义固定部位/条数/属性范围，而是让世界自己定义能穿几件、叫什么、有哪些属性/词条。目标：理论上能做出任意现有规则。**不做**：图灵完备 DSL、玩家端脚本、引擎内 dnd5e 分支。详见 [`RULES-MODEL.md`](./RULES-MODEL.md)（§0 四条确认、§3 数据形状、§6 钩子 API、§13 M9 排期）。 | 备选：a) 纯数据 DSL（表达力不足，复杂规则做不了）；b) 全 JS 规则插件（作者门槛高、客户端无法零脚本、安全面大）；c) 引擎内留 dnd5e 适配接口（等于写死，第二套规则仍要改引擎）。钩子数量固定为 8+1，表达力不够优先扩数据、不无限加钩子；`node:vm` 不是强安全边界，v1 依赖「host 安装内容包 = 受信代码」的 LAN 信任模型。 |

## 第九轮：UI 与资产模型（三屏 + 三条图标路径）补记（2026-11-16）

| # | 决策点 | 结论 | 备选与理由 |
|---|---|---|---|
| 27 | 跑团桌第一优先级的界面与图标资产体系怎么定 | **已定稿（2026-11-16）**：①界面第一优先级 = **人物 / 装备 / 背包三屏**，且**必须引入图标机制**（不能只有文字）；②**不内置图标库**，图标/资产三条获取路径 = 本地导入（归一化后只存 PNG / 净化后 SVG）+ **AI 生成 SVG**（文本模型输出代码，经白名单净化）+ **AI 生图**（风格先做像素风 `pixel-32` 与 2D 游戏风 `game-2d`），无图时渲染**程序化几何徽记**兜底；③图像归一化**纯 JS 自研、零原生依赖**，v1 只收 PNG/SVG（不收 JPEG/WebP），尺寸/格式/体积由内部强制；④插件**只对 OpenAI 兼容协议**：文本生成（出 SVG）与生图各配一套 `baseUrl/key/model`，**不为本地 ComfyUI 改插件代码**，仅另写 `scripts/dev/` 的验证用 shim（不打包、不算正式功能）；⑤玩家头像/立绘可走 host 生图服务（host 可开关 + 限流）或玩家自备接口，默认推荐 host，立绘 **768×1024** 够用；⑥**预览确认才落盘**、支持自定义提示词与重生成，玩家卡支持头像/立绘/表情动作变体与**精灵帧表切分**。详见 [`UI-CONTRACT.md`](./UI-CONTRACT.md)。 | 备选：a) 先做叙事/战报界面（收益低于「一眼看到有什么、穿什么、能打多少」）；b) 内置一套图标包（包体与版权负担，且覆盖不了任意世界）；c) 只做纯文字列表（可用性差，被否）；d) 为本地 ComfyUI 写第二套适配层（维护两套协议，改为 shim 隔离）。三条路径共用同一标准化管线与 manifest 元数据，任何入口都不能绕过尺寸/体积/净化检查。 |

**摘要（4 条）**：三屏优先 = 人物 / 装备 / 背包，图标是界面一等公民、不内置图标库 → 三条路径（本地导入 / AI SVG / AI 生图）+ 几何徽记兜底；只为 OpenAI 兼容协议、纯 JS 归一化、内部强制尺寸/体积/净化、预览确认才落盘；玩家资产走 host 生图服务（可开关+限流）或自备接口，立绘 768×1024，支持表情动作变体与帧表切分；`iconRef`/manifest/归一化管线/投影 DTO/工坊工作台/玩家资产/排期与风险全在 [`UI-CONTRACT.md`](./UI-CONTRACT.md)。

## 第十轮：战斗空间与回合模型（zone-grid + 回合上限 + 行动经济 + GM 工具泛化 + AI 地图生成）（2026-11-16）

| # | 决策点 | 结论 | 备选与理由 |
