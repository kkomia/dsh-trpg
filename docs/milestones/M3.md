E2E 覆盖（真实 HTTP+SSE，假 Agent 代替模型）：
- AI 模式建房 → GM 会话创建 → 6 个工具注册到该 Agent 专属作用域 + 系统提示注入
- 自动开场回合（`【开场】`）→ 叙事广播到房间 SSE
- 玩家加入/落座/提交行动 → 行动 prompt 含「行动者」绑定与「只有这一位玩家行动」，另一个玩家不会被标成行动者
- 假 Agent 调 `roll_check` → 引擎掷骰 → 房间收到带 DC/成败的 dice 事件
- 假 Agent 的 assistant 消息 → 广播为公共叙事事件

反串角保障（机制层，测试覆盖）：
- 行动者由服务端 token→playerId→角色注入 prompt，客户端无法自称他人
- 检定/掷骰只能通过工具走引擎；prompt 明文禁止自算骰子
- 私密信息只能通过 `secret_note`（只发给该玩家，GM 可见）
- GM 工具注册在 Agent 专属作用域（`agentCtx.tools`），不会污染其他会话

## 实机联调记录 2（2026-11-13 晚，HMR 热迭代）

用「预览 bundle + HMR」在**不重启 DSH** 的情况下反复验证，进展与结论：

| 实验 | 结果 |
|---|---|
| `ctx.inject(['agents'])` 惰性注入 | ✅ GM 会话可创建、11 工具注册成功 |
| 裸 Agent（无工具/无系统提示） | ❌ 仍 TRANSPORT → 与工具/提示词无关 |
| `agents.create` + meta.parentSession 锚定宿主会话 | ❌ TRANSPORT |
| `ctx.sessionController.create/resolveAgent`（UI 同款普通会话通道） | ✅ 会话创建/解析/工具注册成功，回合能启动，但模型请求仍 TRANSPORT |
| `selectModel` 显式选模型、reasoningEffort=off、provider=deepseek 覆盖 | ❌ 均 TRANSPORT |
| 独立 `subagent` 工具探针（子 Agent） | ✅ **能正常调用模型并返回 OK** |
| 会话事件监听 | 修复：根上下文收不到 controller 会话事件 → 改为在 **agent.ctx** 上挂 `session/event`，并加 seq 去重 |

**根因判断**：插件自行创建的会话缺少 UI 会话/subagent 子会话所带的那份「模型请求上下文」（DSH 官方 subagent 是继承父会话的 provider/model/授权与连接上下文）。与 provider、reasoningEffort、工具、系统提示都无关。

**下一步方案**：改用 DSH 自带 **subagent 通道**跑 GM 回合——每个玩家行动触发一次 `ctx.subagents.startActivation({provider:'spawn', parent:<宿主活跃会话>})` 子 Agent，GM 工具改为全局注册并按 childId→room 路由；上下文本来就是我们每回合组装的，因此一次性子 Agent 不影响带团连续性。

## 实机联调记录 3（2026-11-13 夜）：AI GM 带团 + 引擎掷骰全链路通过 ✅

采用 DSH 官方 **subagent 通道**后，实机（真实 DeepSeek 模型）完整验证：

- ✅ AI GM 自动开场（模组第一幕「青石镇·悬赏」），中文叙事完整、不替玩家行动
- ✅ 玩家行动 → AI 以 KP 身份回应；需要判定时**主动调用 `roll_check`**
- ✅ **引擎掷骰链路打通**（真实探针记录）：
  - 游说检定：`d20=[2] −1 = 1 vs DC 12 → 失败`，AI 依据失败演出柳掌柜打太极
  - 洞悉检定：`d20=[20] +1 = 21 vs DC 12 → 成功`，AI 依据成功看穿老王隐瞒
- ✅ 骰面事件按服务端规则广播（含技能名、DC、成败），AI 不编造数值

工程结论（已固化进实现）：
- `startActivation` 的 `prompt` 必须是内容块数组；字符串会报 `content.some is not a function`；
- 子 Agent 在 `startActivation` 返回前就开始执行工具 → childId→room 映射必须**调用前**写入；
- 热重载会残留旧世代同名工具注册 → 工具名加**世代后缀**，GM 提示词动态使用后缀名（干净重启后也会自然唯一）；
- 不同宿主会话的子 Agent 池独立 → 池满时轮换父会话；续团房间不自动重开。
