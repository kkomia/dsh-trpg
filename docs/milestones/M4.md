## 已实现机制

- **玩家本地角色卡库**：浏览器本地保存；支持导入角色卡 JSON、把预制卡存为本地卡、落座时上传、导出为 JSON、删除；散团后「合并成长到卡」把 GM 奖励物品叠进背包（XP 记在成长档案，卡 schema 暂无 xp 字段）。
- **云成长回传（客户端）**：GM 的 award 事件按 `<roomId>:<seq>` 去重累计到 localStorage，侧栏显示 XP 与物品；可一键导出「成长 JSON（角色卡补丁）」与「战报 Markdown」。
- **存档**：每次房间事件触发 debounce（800ms）快照到 `$DSH_HOME/profile-data/<profile>/dsh-trpg-table/rooms/<roomId>.json`；tmp→rename 原子写；关闭时强制 flush。
- **续团**：插件启动先恢复房间（含玩家 token，客户端 localStorage 里的 token 重连即可继续），再拉起 HTTP 服务；AI 模式房间重新创建 GM 会话，GM「最近事件」从存档事件继续。
- **真人 GM**：GM 指令只接受 host token；场景与奖励均为服务端投影（奖励只到目标玩家，GM 可见）；旁白走与 AI 相同的 narration 通道。
- **双 GM 模式**：human 模式不启动 Agent（已有单测）；AI 模式可随时用 GM 控制台人工干预。

## UI v2（2026-11-13 深夜，主理人反馈后重做）

> **历史方案，已被 v3 取代**：本节 UI v2（`main` 整页面板 + 自绘叙事流 + 插件行动输入框）在 M6 被「对话原生牌桌」v3 取代，面板代码已删除，不再作为现行指引。当前 UI 形态见 [DESIGN.md §9](../DESIGN.md)。以下内容仅作历史记录保留。

主理人反馈：跑团 UI 全部塞在对话输入框下方的 `conversation.composer.dock` 一条里（旁边就是 token/速度那一行），
当聊天窗口太憋屈，要「把对话主区域当作跑团的对话区」。

改动：

- 撤掉 dock 注册；跑团桌改为**主区域整体面板**：`main` 槽位 key=`trpg`（`ctx.slots.register`，组件由 `inject` 传入 `goHome`）。
- 页面结构：顶栏（团名/阶段/GM 模式/场景/邀请码/人数 + 锁房/GM 控制台/退出/返回对话）
  → 中间叙事对话流（GM 气泡、玩家气泡右对齐、骰子卡片居中、战斗/场景/奖励卡片）
  → 底部行动输入框（Enter 发送、Shift+Enter 换行、悄悄话给 GM）→ 右侧栏（玩家席/落座/角色卡库/GM 控制台/掷骰/成长战报）。
- 没有房间时同一页面渲染大厅（房主地址、建房、加入、说明）。
- 入口：`sidebar.panellist` id=`trpg`（骰子图标）与 `conversation.session.header.actions`「🎲 跑团桌」按钮（`ctx.layout.selectPanel('trpg')`）；页面内「返回对话」用 `selectPanel(null)`。
- 需要 Session 之外的宿主：主区域面板不依赖会话，空白会话也可进（`conversation.view` 在空白会话不渲染，已弃用）。

验证：`cordis_inspect_query` 确认 `main` 占用者含 `trpg`（active）、`sidebar.panellist` 含 `trpg`、`composer.dock` 已无本插件；
页面在运行中的 DSH 里实际渲染过大厅与房间视图（AI GM 真实开场叙事以 GM 气泡显示）。
